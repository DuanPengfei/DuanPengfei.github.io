  <h2 class="codex-eval-heading">结论</h2>
  <p class="codex-eval-copy">模型选择不是寻找“最高分”，而是验证某个模型在明确任务、约束与预算下是否更可靠。公开榜单适合形成候选池，不能直接代替内部决策：提示模板、上下文长度、工具环境和评分者差异，都可能改变排序。评测开始前应先写出使用场景、失败代价和最低可接受线，再选择指标。</p>

  <h2 class="codex-eval-heading">评测矩阵</h2>
  <div class="codex-eval-table-wrap">
    <table class="codex-eval-table">
      <thead><tr><th>维度</th><th>建议观察</th><th>常见误区</th></tr></thead>
      <tbody>
        <tr><td>任务质量</td><td>正确率、完整性、可执行性</td><td>只看通用知识题</td></tr>
        <tr><td>稳定性</td><td>重复运行方差、长上下文退化</td><td>只跑一次取最好结果</td></tr>
        <tr><td>效率</td><td>端到端时延、人工返工、总成本</td><td>只比较单次令牌价格</td></tr>
        <tr><td>安全</td><td>越权调用、敏感信息泄露、拒答边界</td><td>把拒答率当唯一指标</td></tr>
      </tbody>
    </table>
  </div>

  <h2 class="codex-eval-heading">执行方法</h2>
  <p class="codex-eval-copy">样本应覆盖日常、高价值、边界和对抗任务，并保留真实分布，避免困难样本把结果拉向并不存在的生产场景。对主观输出采用匿名成对比较，随机交换答案顺序；对可判定任务优先使用可执行验证。每个结论同时报告样本量、置信区间、失败案例和评测版本。若两个模型质量接近，应以尾延迟、返工率和风险成本做最终取舍。</p>

<script>
(() => {
  document.querySelectorAll('[data-codex-report="evaluation-for-decisions"]').forEach((root) => {
    if (root.dataset.codexEnhanced === 'true') return;
    root.dataset.codexEnhanced = 'true';

    const boxes = [...root.querySelectorAll('[data-codex-eval-check]')];
    const score = root.querySelector('.codex-eval-score');
    const bar = root.querySelector('.codex-eval-meter-bar');
    const update = () => {
      const done = boxes.filter((item) => item.checked).length;
      score.textContent = `${done} / ${boxes.length}`;
      bar.style.width = `${boxes.length ? done / boxes.length * 100 : 0}%`;
    };

    boxes.forEach((box) => box.addEventListener('change', update));
    update();
  });
})();
</script>
